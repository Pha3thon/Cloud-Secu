16. STANDING CONTENT RULES
────────────────────────────────────────────────────────────────
- Three Slide Formats:
  • 'standard': Default theory presentation with title, body, optional scene animation, and optional reference.
  • 'eli5': "Explain Like I'm 5" (tagged "In Simple Words"). 2–3 short sentences max. Zero jargon. Concrete everyday
    child-friendly analogy (toys, home, family, food, school — no abstract corporate analogies). Pure plain language only
    (no citations or 📚 references). Retains scene animation.
  • 'official-definition': Formal standards definition (tagged "Official Definition"). Contains ONLY the formal definition
    from the originating standard or standards body (e.g. NIST, RFC, ISO, IANA, MITRE, FIRST.org). No repetition of
    analogies or re-explanations. Deliberately dry and precise.
    Must include:
      - standardName: Standards body and identifier (e.g. "NIST SP 800-125", "RFC 1918")
      - standardFullTitle: Official title of the publication
      - definitionText: The quoted or closely paraphrased standard text
      - sourceUrl: Real, clickable public URL (rendered prominently as an external link chip: "View source: [Name] ↗")
      - bridgeLine: Exactly one line bridging back to Slide 1's ELI5 analogy
      - sceneId: null (no scene animation on official definition slides)
  • Text-to-Speech (TTS): Handled via src/hooks/useReadableSlideText.js. Reads ELI5 plain language directly; on official
    definition slides, reads definition + standard name and cleanly substitutes "source link available on screen" instead
    of reading the raw URL string aloud.
- ELI5 → Official Definition Pairing (Revision 11):
  All 16 core foundational terms across M1 must be presented as a strict two-slide pair:
  1. Slide 1 (eli5): Child-simple everyday analogy.
  2. Slide 2 (official-definition): Formal standard definition + clickable sourceUrl + bridgeLine.
- Example Personas & Names Convention:
  Example personas/names in analogies and scenarios: Indian names or Indian-film references only,
  varied across a module, never clustered from one film, never Western placeholder names (John/Alice/Bob).
- Natural-Value Answers:
  Lab flags use natural values produced by standard commands/tools (IPs, hashes, modes, flags),
  not artificial multiple-choice letters or dummy strings.
- Honest Referencing:
  Real public standards only (NIST, RFC, ISO, MITRE, FIRST) — verified working URLs, no invented document numbers.

20. CONTINUOUS TIMELINE ANIMATION ENGINE & SLIDE CHROME (Revision 12)
────────────────────────────────────────────────────────────────
Continuous Animation Engine       → src/hooks/useSceneLoop.js
  - Driven by requestAnimationFrame (rAF), not discrete setTimeout/setInterval.
  - Returns: progress (0.0..1.0 continuous float), elapsedMs, totalMs, isPaused, play(), pause(), seek(progressValue), seekTo(val).
  - Ambient autonomous loop with loopPauseMs between cycles.
  - Sentence hover passes activeStepOverride to pause & seek to target progress smoothly.
  - prefers-reduced-motion: locks to progress=1.0 with static final frame, rAF stopped.
Interpolation Utility             → src/utils/interpolate.js
  - interpolate(progress, inputRange, outputRange, { ease: 'linear'|'easeInOut'|'easeIn'|'easeOut', clamp: true })
  - Supports numeric values and hex/RGB color interpolation (lerpHex).
  - Helper functions: clamp, lerp.
Scrub Bar (Live Clock & Seeking)  → src/components/scenes/SceneScrubBar.jsx
  - Live elapsed/total time readout ticks every frame with rAF.
  - Draggable handle calculates continuous ratio and calls seek(progress) for real-time visual scrubbing.
  - Play/Pause icon freezes/resumes rAF loop directly.
  - Leftover discrete step dots below frame removed; scrub bar handles all scrubbing on hover.
Slide Chrome Pattern (Part C)     → src/components/slides/TheorySlide.jsx
  - Above-card context chrome: Module label on left, "Card X of Y" on right.
  - Full-width H1 slide title above card.
  - Horizontal Segmented Progress Bar: 1 pill segment per slide in current topic (filled = passed/current, muted = upcoming). Scoped to topic sequence.
  - Inside Card Top Bar:
    - Small rounded tag chip (e.g. "IN SIMPLE WORDS", "OFFICIAL DEFINITION", "IDEA").
    - Inline Accessibility controls: "Auto-Read: OFF/ON" toggle and "Listen to Card" trigger.
  - Inside Card Body:
    - Cisco-style centered 16:9 continuous SVG scene animation with hover scrub bar.
    - Narrative text & interactive elements below scene.
  - Card Footer:
    - "< Back" on left, "Next >" / "Finish & Unlock Lab" on right.
